# dtcg-editor Project History

Running log of shipped features, architecture decisions, and the current API/config surface. Governance-level principles (tech stack, architectural constraints, approved dependencies) live in `.specify/memory/constitution.md`, not here — this file is pure history, updated by `archive-task` as each feature merges.

## Features

- **Configured Token Directory Viewer**: scans a configured directory for DTCG token files, parses each with `token-core`, and lets the user browse valid files as a navigable token tree via the Next.js web app; invalid files are flagged individually without blocking the rest. (`docs/specs-archive/202607251128-configured-token-directory-viewer/`)
- **Enforce Conventional Commits**: local `commit-msg` git hook (commitlint) and an interactive `pnpm commit` CLI (commitizen) enforce a fixed Conventional Commits type/scope standard, both reading one shared config so they can't drift; documented in `CONTRIBUTING.md`. CI-level enforcement is deferred (`docs/backlog.md`). (`docs/specs-archive/202607251245-enforce-conventional-commits/`)
- **Migrate to Result-Pattern Error Handling**: the token read chain (`token-core` parsing + all `web-app` consumers) returns `Result`/`ResultAsync` instead of throwing, per the Error Handling constraint above; a new `@dtcg-editor/errors` package provides the shared `UnknownError`/`Logger`; closes a previously-unhandled `readdir`-crash gap in `scanTokenDirectory` along the way. (`docs/specs-archive/202607251455-migrate-to-result-pattern-error-handling/`)
- **Bootstrap CI (GitHub Actions)**: a GitHub Actions workflow runs `pnpm build`/`lint`/`test` (via Turborepo) on pull requests into `main` and on pushes to `main`; type checking is covered by `build` alone (`tsc`/`next build`), so no separate typecheck step exists. CI-level Conventional Commit enforcement remains deferred (`docs/backlog.md`). (`docs/specs-archive/202607251627-bootstrap-ci-github-actions/`)
- **Edit Dimension Tokens in Browser**: Dimension tokens' name/`$value`/description are editable in the web app's token tree view and saved back to their file's JSON on disk in one batch write; every other token type stays read-only. First implementation of `token-core`'s `serialize()`/round-trip path and of the Token-Type Package Contract (`@dtcg-editor/token-type-contract` + `@dtcg-editor/token-type-dimension`, the first concrete token-type package). (`docs/specs-archive/202607270923-edit-dimension-tokens-in-browser/`)
- **Migrate config.ts to Result Pattern**: `apps/web-app/lib/config.ts`'s `loadConfig` now returns `Result<Config, ConfigError>` via `fromThrowable`/`.andThen` instead of throwing, and `instrumentation.ts`'s `register()` branches on that `Result` instead of `try`/`catch`; completes the second, previously out-of-scope call path (startup config loading) for the earlier Result-pattern migration. `getConfig()`'s public `(): Config` signature and all four request-time call sites are unchanged. (`docs/specs-archive/202607280011-migrate-config-result-pattern/`)
- **CI-Level Conventional Commit Enforcement**: a second, parallel `commitlint` job (sibling to the existing `ci` job) in `.github/workflows/ci.yml` lints real commit messages/PR commit ranges via a hand-rolled `pnpm exec commitlint --from/--to` invocation against the existing `commitlint.config.cjs` (no third-party GitHub Action, no new config); runs on both `pull_request` and `push` events, with a `git rev-list --max-parents=0` fallback for the push zero-SHA edge case. `CONTRIBUTING.md` now forbids merge commits in feature branches and requires rebasing onto `main` instead. Closes the CI-level-enforcement gap both Bootstrap CI and Enforce Conventional Commits deferred. (`docs/specs-archive/202607280019-ci-conventional-commit-enforcement/`)
- **CLI to Bootstrap `dtcg-editor.config.json`**: a new `apps/web-app/scripts/init-config.ts` command (`pnpm --filter web-app run init-config`) scaffolds `dtcg-editor.config.json`, either interactively (`node:readline/promises` prompt) or flag-drivenly (`--tokens-dir`, `--force`, `--help`, parsed via `node:util`'s `parseArgs`), validating against the same exported `ConfigFileSchema` `instrumentation.ts` uses at startup so the two can never drift. No new runtime dependency; `engines.node` bumped to `>=26.5.0` and CI's Node version bumped to `26` so the script's native `.ts` execution needs no flags. (`docs/specs-archive/202607280827-cli-bootstrap-config/`)
- **UI-Layer Result Consumption Conventions**: replaces the Error Handling constraint's prior "undefined for now" UI-layer deferral with a concrete, evidence-derived convention — Server Components exhaustively branch every named error before falling back to a generic message (`app/tokens/[...path]/page.tsx`'s `describePageError`, fixing a previously-generic `FileNotFoundError` fallback), Client Component hooks track fetch outcomes as status-enum-plus-discriminated-union state instead of thrown exceptions (`useSaveTokenEdits`, extracted from `TokenTree.tsx`'s prior ad hoc logic, as the reference implementation), and a root `app/error.tsx` boundary is scoped strictly to genuinely unexpected exceptions. `app/api/tokens/[...path]/route.ts`'s error responses gained an additive `kind` discriminant so the wire body is `SaveError`-shaped. (`docs/specs-archive/202607280829-ui-result-consumption-conventions/`)
- **Fix Edge Runtime Warning for `process.exit` in `instrumentation.ts`**: isolates the Node-only fatal-startup-exit path (`console.error` + `process.exit(1)`) behind a dynamic import of a new `apps/web-app/lib/fatal-startup-error.ts` module, mirroring the existing `config.ts` dynamic-import pattern, so Turbopack's Edge Runtime static-analysis pass no longer flags `process.exit` in `instrumentation.ts`'s own source — a structural fix, not a suppression. (`docs/specs-archive/202607280933-instrumentation-edge-runtime-process-exit/`)
- **Inject Dependencies by Default**: establishes and enforces the Dependency Injection for I/O/Platform Externalities constraint (see Architectural Constraints above) across every existing call site — `fs` (`read.ts`/`scan.ts`/`write.ts`/`config.ts`/`init-config.ts`, real-defaulted from the new `apps/web-app/lib/platform/node-fs.ts` adapter), `fetch` (`useSaveTokenEdits.ts`), and `process.exit`/`console.*`/`process.env` (`instrumentation.ts`'s new `runRegister(deps)`/`register()` split). Rewrote four fs-touching test files off real-temp-dir (`mkdtemp`) fixtures onto hand-rolled mocked-fs fakes, added the previously-missing `write.test.ts` and a new `instrumentation.test.ts`, and added ESLint `no-restricted-syntax`/`no-restricted-imports`/`no-restricted-globals` rules to both `eslint.config.mjs` files so a new direct call site outside its designated file is a lint error, not just a documented convention. No new dependency added. (`docs/specs-archive/202607281409-inject-dependencies-by-default/`)
- **Reformat Repo to Tabs**: adds Prettier (`useTabs: true`) as the repo's formatter plus `.editorconfig`/`.prettierignore`, reformats every existing Prettier-supported file (147 files) to tab indentation with zero behavioral change (`build`/`lint`/`test` verified identical before/after), and adds a `pnpm format:check` script wired into CI's existing `ci` job so formatting can't drift back to spaces. (`docs/specs-archive/202607281440-reformat-repo-to-tabs/`)
- **Editable Group Names and Visible Field Labels**: non-root groups in the token tree (`TokenTree.tsx`) become renameable through the same batched edit/save pipeline tokens already use — `token-core`'s `applyTokenEdits` gained group-rename support (with cascading descendant `path` updates and a depth-based stable sort fixing a same-batch ordering hazard), mirrored client-side in `edit-state.ts`, and accepted by `route.ts` for name-only group edits. Every field in the tree (editable and read-only, including `DimensionEditor`'s value/unit inputs) now has a real visible `<label>` instead of relying solely on `aria-label`, preserving today's per-row accessible-name uniqueness. (`docs/specs-archive/202607281844-editable-group-names-and-visible-field-labels/`)
- **Save Button as a Call-to-Action Component**: extracts the token tree's inline `<button>` into its own `apps/web-app/components/SaveButton.tsx` component (+ `SaveButton.module.css`), restyled as a larger, rounded, solid-accent CTA with `:hover`/`:focus-visible`/`:disabled` states and a hand-rolled inline disk-icon SVG (no new dependency). New `--accent`/`--accent-hover`/`--accent-foreground` CSS custom properties added to `globals.css` (light + dark), introduced generically for future CTAs. Accessible name and `disabled` semantics unchanged; existing `TokenTree.test.tsx` assertions pass unmodified. (`docs/specs-archive/202607282347-save-button-as-a-call-to-action-component/`)
- **Config-Driven Token Editor Components**: `apps/web-app/dtcg-editor.config.mts` (committed, calling a new `defineConfig({ tokensDir, extensions })` helper) replaces `dtcg-editor.config.json`; `extensions` is an array of `{ filter, editor }` pairs letting a user override which React component edits a subset of tokens, merged by `defineConfig` with this repo's built-in defaults (currently just `DimensionEditor` for `"dimension"`, sourced from `@dtcg-editor/token-type-dimension`'s `dimensionTokenType`) so zero-config behavior is unchanged. `TokenTree.tsx` resolves the editor per token via `resolveEditorForType` (first-match-wins, user entries ordered ahead of defaults) instead of a hard-coded `DimensionEditor` import; `edit-state.ts`/`route.ts` validation/serialization untouched (UI-selection-only scope). (`docs/specs-archive/202607292258-config-driven-token-editor-components/`)
- **Prettier Pre-Commit Formatting**: a new `.husky/pre-commit` hook runs `format-staged.cjs`, which gets the commit's staged files from git, runs `prettier --write --ignore-unknown` on exactly that set, and re-stages the result — so a commit can never introduce unformatted code without a manual `pnpm format` step. Hand-rolled over adding `lint-staged` as a dependency, per the Minimal Dependencies constraint; git/prettier calls are injected via an `exec` parameter for unit testability. (`docs/specs-archive/202607300736-prettier-pre-commit-formatting/`)
- **Accessibility Testing**: two-tier automated WCAG 2.2 AA checking for `apps/web-app` — a Vitest Browser Mode project (`@vitest/browser` + `@vitest/browser-playwright`, real Chromium) runs `axe-core` against `FolderOverview`, `SaveButton`, `TokenTree`, and the dimension token editor; a `@playwright/test` suite checks the home/tokens/error pages plus a full keyboard-only browse → open → edit → save flow. Both are enforced (non-warn-only) under `pnpm test`/`turbo run test` and wired into CI. Found and fixed two real issues along the way: a WCAG 1.4.3 color-contrast violation in `TokenTree`'s field labels, and a `process is not defined` crash from `next/link`'s internals in the real-browser test environment. (`docs/specs-archive/202608011523-accessibility-testing/`)
- **Generic Fallback Token Editor**: any token whose `$type` is a spec-valid DTCG type (`packages/token-core`'s new canonical `DTCG_TOKEN_TYPES` list) but has no custom editor registered becomes editable via a generic JSON-text editor; tokens with a non-DTCG `$type` stay read-only and are now flagged as "non-standard" in `FolderOverview` rather than silently treated like any other uneditable token. `TokenEditorExtension` changes from `{ filter, editor }` to `{ type, editor }`, with `defineConfig` validating `type` against the canonical list at config-load time; both client (`TokenTree.tsx`'s `canEdit`) and server (`route.ts`'s edit-authorization gate) generalize off their prior dimension-only hard-coding. (`docs/specs-archive/202608012104-generic-fallback-token-editor/`)
- **Support for Colour (Color) Tokens**: adds `@dtcg-editor/token-type-color` for DTCG's `color` `$type` (all 14 2025.10 Color module colorSpaces + legacy bare-hex `$value`), a CSS-native swatch preview, non-blocking per-colorSpace range validation, and a full `ColorEditor` UI. Originally shipped read-only; once `fallback-token-editor` merged and generalized `canEdit`, a follow-up fix (this same worktree) extended that generalization to validate any built-in type's value against its own contract schema — both client-side (`TokenTree.tsx`) and server-side (`route.ts`'s PATCH handler, which previously validated only `dimension` edits) — before allowing/accepting an edit, unlocking color-token editing safely and closing a validation gap that predated this feature. (`docs/specs-archive/202608021545-support-for-colour-tokens/`)
- **Configurable Color Spaces + Interactive Color Picker**: lets a host app restrict which of the 14 DTCG `colorSpace` values `ColorEditor` offers, via a new generic `editorOptions`/`editorOptionsSchema` config channel (`TokenEditorExtension.editorOptions` validated against `TokenTypeContract.editorOptionsSchema` by `defineConfig`) and `token-type-color`'s `ColorEditorOptions`/`defineColorConfig`. Also adds a native `<input type="color">` picker to both the object and legacy-hex color editors, backed by `colorjs.io` for sRGB-hex ⇄ any-colorSpace conversion, derived fresh from the current value on every render so it can't drift from the numeric/hex fields; picking never touches alpha. `TokenEditorExtension.type` reverts from plain `string` back to the `DtcgTokenType` union along the way. (`docs/specs-archive/202608022222-configurable-color-spaces-interactive-color-picker/`)
- **Migrate ESLint + Prettier to Biome**: replaces ESLint (`typescript-eslint`, `eslint-config-next`) and Prettier repo-wide with Biome 2.5.8 as the single lint-and-format tool; all 11 Dependency Injection for I/O/Platform Externalities rules (see the constraint above) reproduced 1:1 via native Biome rules (`noExplicitAny`, `noRestrictedImports`, `noRestrictedGlobals`, the `domains.react` hooks pair) plus 7 hand-authored GritQL plugins (`biome/*.grit`) for the restricted-call-expression patterns Biome has no native equivalent for, with every documented per-file exemption preserved. `eslint-config-next`'s Next.js-specific lint coverage is a permanently accepted, documented gap (no Biome plugin ecosystem or third-party fill exists). First of two sequenced features resolving the "Upgrade `typescript` to v7" backlog item — removes `typescript-eslint`'s `typescript<6.1.0` peer-range blocker, since Biome's own type-inference engine never touches `tsc`'s Compiler API. (`docs/specs-archive/202608161600-migrate-eslint-prettier-to-biome/`)
- **Token-Core Parsing Consolidation & Token-Editor Rename**: moves every DTCG token type's structural value schema and derived type definitions (`ColorValueSchema`/`ColorObjectValueSchema`/`LegacyHexColorValueSchema`/`DimensionValueSchema`) into `token-core`, the single source of truth for DTCG-compliance parsing across all token types. `token-type-color`/`token-type-dimension`/`token-type-contract` renamed `token-editor-color`/`token-editor-dimension`/`token-editor-contract` and trimmed to hold only `Editor` UI, editor config, `TokenTypeContract` wiring, and (for color) a new `src/utils/` subfolder grouping value-adjacent utilities that are *not* structural parsing (`range-validation.ts`'s `checkColorValueIssues`/`COMPONENT_RANGES`, `conversion.ts`'s native color-picker interop, `css-color.ts`'s CSS rendering) — none of which moved to `token-core`, since none is needed by a headless DTCG consumer. Every `apps/web-app` consumer repointed with zero intended behavior change, verified against a captured pre-refactor baseline. (`docs/specs-archive/202608162249-token-core-parsing-consolidation-and-token-editor-rename/`)

## API

| Method | Path                  | Description                                                                                                                                                                                                                                                                                                                                                 | Auth Required |
| ------ | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| GET    | /api/tokens           | Lists discovered token files under the configured directory, each marked valid/invalid and (for valid files) standard/non-standard; 500 on scan failure                                                                                                                                                                                                     | No            |
| GET    | /api/tokens/[...path] | Returns a single parsed token document; 400 (path traversal), 404 (not found), 422 (parse failure), or 500 (unexpected failure) on error                                                                                                                                                                                                                    | No            |
| PATCH  | /api/tokens/[...path] | Applies a batch of edits (rename/value/description) to any standard-DTCG-type token and/or group renames (name only) to the file and writes it back in one operation; 400 (invalid request/value, rename collision, non-standard type, value/description on a group, path traversal), 404 (not found), 422 (parse failure), or 500 (write failure) on error | No            |
