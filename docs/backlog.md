- [ ] Make `token-core` resolver-aware: move the DTCG Resolver Module's mode-composition *algorithm* (currently `apps/web-app/lib/tokens/reference-index.ts`'s `lookupForMode` — given a token's multiple mode-tagged definitions, pick the one matching the requested mode, else fall back to the last-listed one) into `token-core` as a first-class, spec-defined concept, not an app-specific one. This is a definite, wanted refactor (not a "maybe," unlike other items on this list) — the mode-selection rule itself is DTCG spec behavior (a `tokens.resolver.json` set/modifier composition, same territory `@styleframe/dtcg`'s `mergeDocuments`/resolver module covers, per the top item on this list and `docs/research/styleframe-dtcg-spike.md`'s Pass 2/4), so it belongs in the core engine alongside `resolveEffectiveDocument`/`classifyValue`, not scattered into whichever host app happens to need it. **Explicitly does NOT mean adding filesystem/directory-scanning to `token-core`** — `token-core` stays exactly as file-I/O-free as it is today (see its `README.md`'s "What this package deliberately does not do"); only the resolution *algorithm* moves, taking an already-in-memory, host-supplied representation of "this path's candidate definitions across modes" as input (shape TBD at spec time — likely a `TokenDefinition[]`-like structure, not raw files), mirroring how `resolveReference`/`ReferenceLookup` already separate "the algorithm" (owned by `token-core`) from "how to find a node" (owned by the caller). `reference-index.ts`/`resolver-file.ts` would keep the directory-scanning/`tokens.resolver.json`-parsing/`ReferenceIndex`-building parts, just delegating the actual mode-pick to the newly core-owned function. Raised while reviewing `008-token-core-coherence`'s effective-field-resolution work (2026-08-26) — asked directly whether `lookupForMode` belonged in `token-core`; the answer at the time was "no, not as-is" (it's built from filesystem-touching `ReferenceIndex`/`documentsByFile`), but this item captures the follow-up: extract just the reusable algorithmic core, not the whole function verbatim.
