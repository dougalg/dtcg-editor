# Code Review: CLI to Bootstrap `dtcg-editor.config.json` (commit `e282094`, dedup fix `53566f3`)

## Summary

A new `apps/web-app/scripts/init-config.ts` CLI scaffolds `dtcg-editor.config.json` for a new user, in both an interactive `readline/promises`-driven wizard and a flag-driven non-interactive mode (`--tokens-dir`, `--force`, `--help`), validating against the exact `ConfigFileSchema` `instrumentation.ts` uses at startup (exported from `apps/web-app/lib/config.ts` with no schema changes). Follows the repo's established injectable-core/thin-wrapper split (`runInitConfig(io: InitConfigIO)` holds all behavior; a thin `main()` touches real `process.argv`/`process.stdin`/`process.stdout`/`process.exit`), matching the existing Route Handler precedent in `docs/project.md`. No new runtime dependency: flag parsing uses `node:util`'s built-in `parseArgs`, prompting uses `node:readline/promises`, matching the Minimal Dependencies constraint's built-ins-first bias. `engines.node` bumped `>=20` → `>=26.5.0` (current latest Node release) and CI's `actions/setup-node` bumped `"22"` → `"26"` in the same change, so the script's native `.ts` execution needs no `--experimental-strip-types` flag. 10 co-located Vitest cases in `init-config.test.ts` exercise `runInitConfig` via injected IO, no child-process spawning. All 10 acceptance criteria independently re-verified. No critical or major issues found. **Ready to merge.**

### Architectural Constraints (docs/project.md) — independently checked

- **Minimal Dependencies**: no new `package.json` entries in either the root or `apps/web-app`; `node:util`'s `parseArgs` and `node:readline/promises` are both Node built-ins, consistent with the "built-ins are the default" bias and requiring no Minimal Dependencies sign-off (that constraint governs third-party packages only).
- **Error Handling (Result Pattern)**: `runInitConfig` returns `Result<string, string>`; the file write (`writeFileSync`) is wrapped via `fromThrowable` at the point it's called, matching `config.ts`'s existing pattern for `readFileSync`/`JSON.parse`. The thin `main()` wrapper is the sole place that unwraps the final `Result` and calls `process.exit`.
- **Validation at the Edges**: the CLI is a new edge writing config data that `instrumentation.ts` later reads; it validates via the identical `ConfigFileSchema` rather than a hand-rolled or duplicated check, so the two validation points cannot silently drift.
- **TypeScript Strictness / Token-Type Package Contract / Round-Trip Fidelity**: not applicable — this feature touches only config-bootstrapping tooling, no token parsing/serialization or token-type package code.
