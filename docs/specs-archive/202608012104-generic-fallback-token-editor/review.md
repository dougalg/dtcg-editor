# Code Review: Support for Colour (Color) Tokens

## Summary

Clean, well-scoped implementation that mirrors `token-type-dimension`'s package shape exactly, correctly stops short of making color tokens editable (per the deliberate sequencing decision deferring that to `fallback-token-editor`), and gets the DTCG 2025.10 Color module's per-colorSpace ranges right — verified directly against the live spec page during this review, not just trusted from `plan.md`. `pnpm build`, `pnpm lint`, `pnpm format:check`, and `pnpm test` (165 tests across `token-core`/`token-type-color`/`web-app`, plus 4 Playwright e2e specs) all pass locally. A live dev-server spot check of `sample_data/color_scale.tokens.json` confirms the swatch renders correctly for `srgb`, `hsl`, `oklch`, `display-p3`, a `"none"` component, and a legacy hex value, and that an out-of-range `hsl` token still renders with its issue visibly displayed in red — AC-04/AC-05 hold up under real rendering, not just unit assertions. One Minor finding: the error message shown for a _structurally_ invalid color value (wrong colorSpace, wrong component count, etc., as opposed to an in-range-schema-but-out-of-range value) is Zod's generic "Invalid input", which doesn't actually tell the user what's wrong — a real but non-blocking UX gap. Ready to merge after considering that fix.
