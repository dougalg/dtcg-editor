# Code Review: Prettier Pre-Commit Formatting

## Summary

The core logic (`format-staged.cjs`) is well-designed, idiomatic for this repo (DI via injected `exec`, array-form `execFileSync` args, `npx --no --` matching the existing hook style), fully unit-tested (9/9 passing), and independently verified here to correctly format staged files, leave unstaged files untouched, respect `.prettierignore`, and abort the commit on a Prettier syntax error. `pnpm lint`, `pnpm test`, and `pnpm format:check` all pass repo-wide.

However, a real `git commit` run in this exact worktree just now proved the new `.husky/pre-commit` hook **does not fire** — a deliberately-unformatted staged file committed cleanly, unformatted, with no error. This is because `core.hooksPath` is a shared, absolute path (`/Users/dougalgraham/Projects/dtcg-editor/.husky/_`) anchored to the main worktree, and husky's `h` shim resolves the actual hook body from that same fixed main-worktree path — not from whichever worktree/branch `git commit` is invoked in. The main worktree's `main` branch doesn't have `.husky/pre-commit` yet (feature unmerged), so the shim's `[ ! -f "$s" ] && exit 0` guard silently no-ops. This directly contradicts `plan.md`'s Step 6 and `impl-summary.md`'s claim that AC-01/02/03/04 were confirmed via "real end-to-end commits" in this worktree — those commits could not have exercised the actual hook as currently configured. Needs a fix before merge: either correct/caveat the verification claim, or re-verify for real once merged to `main`, and document the worktree limitation so it isn't silently assumed to work everywhere it's used.
